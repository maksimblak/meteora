# 11 — Адаптер Meteora Data API под реальный формат

**Требования:** R17, G04, D04, D06
**Зависит от:** 02, 10
**Зона:** `src/providers/` · `src/market/` · `src/domain/features/` · `tests/providers/` · `tests/market/` · `tests/domain/`
**Волна:** 7
**Ревью:** да — общие рыночные данные, на них стоит каждое решение
**Модель:** сильная

## Что должно заработать

Бот получает данные о пулах с настоящего Meteora DLMM Data API, а не только с придуманных фикстур: весь universe, постранично, с правильными типами и временем. Если коротких окон в API нет, бот честно строит короткое окно из того, что есть, и пишет в решении, откуда взялось число.

## Разделы спецификации

Истории 17, 36; §5.3; §6.1 с поправкой D04; §6.2; §6.6 (объём в минуту); граница `domain.market` и `adapters.providers`.

## Критерии приёмки

- [ ] адаптер принимает реальные ответы `dlmm.datapi.meteora.ag`: числа переводятся в `Decimal` через строку, без binary float на границе домена; `created_at` и прочие времена из epoch в мс — в timezone-aware UTC
- [ ] постраничный обход всего universe с ограниченной конкурентностью и соблюдением rate limit; частичная или битая страница даёт provider degradation, а не падение sync
- [ ] нет окна 5m — короткое окно берётся из наименьшего доступного, нормируется в минуту и несёт пометку источника окна в snapshot и decision record; без look-ahead
- [ ] тесты адаптера идут на записанных и очищенных ответах реального API, сохранённых в тестовых фикстурах; старые выдуманные фикстуры заменены или явно помечены
- [ ] ручная smoke-команда (не в обычном прогоне тестов) делает один read-only проход universe по реальному API без ключей и печатает сводку: сколько пулов, сколько отклонено адаптером и почему
- [ ] пороги `guide-v1` (объём в минуту, объём к ликвидности, base fee, капа) получают значения из реального ответа; поля, которых API не даёт, остаются `UNKNOWN` по правилам §6.6
- [ ] (D06) `PoolSnapshot` несёт active bin id пула и decimals обоих токенов — из Data API, а если там нет, то из аккаунта LB pair и mint-аккаунтов через RPC; отсутствие даёт `None`, и вход не-SHADOW по-прежнему закрыт
