## Что должно заработать

## Критерии приёмки

- [ ] ключ новой позиции создаёт executor в момент команды открытия, подписывает им инициализацию позиции и возвращает адрес позиции в receipt; ключ не покидает executor и не попадает в логи, receipt и events; Python берёт адрес позиции только из receipt и больше его не выводит
- [ ] контракты обновлены согласованно в TypeScript и Python: если изменение несовместимо, это новая версия контракта, старая отклоняется явно; общий JSON corpus в `contracts/execution/` проходит обе стороны
- [ ] price impact обменной части входа и выхода берётся из котировки официального `@meteora-ag/dlmm` и входит в результат симуляции; превышение лимита из политики отклоняет команду; readiness для LIVE — ready, только когда кошелёк, RPC и измерение price impact доступны
- [ ] executor сверяет active bin пула из аккаунта LB pair с якорем команды; расхождение больше допуска отклоняет команду; decimals токенов из mint-аккаунтов возвращаются в симуляции, Python переводит количества в base units по ним, вход с разными decimals больше не отклоняется только из-за этого
- [ ] ни один тест и запуск по умолчанию не отправляет транзакцию; тесты executor идут на фейковом соединении; ручная процедура проверки на devnet с тестовым кошельком описана и по умолчанию не запускается
- [ ] (D07) read-only `POST /v1/quotes` во внутренней сети: пул и эталонный размер → price impact и ожидаемый выход по котировке официального SDK, без кошелька и без подписи; работает в профиле без wallet; Python-клиент в `src/execution/` с тем же контрактным подходом (версия, corpus)
- [ ] (D08) выход (REMOVE/CLOSE) не отклоняется по price impact обмена, которого executor не делает: impact показывается и пишется в аудит; код причины отказа симуляции доходит до результата входа, alert и approval preview
