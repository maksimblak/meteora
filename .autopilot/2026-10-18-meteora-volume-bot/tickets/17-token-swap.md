## Что должно заработать

После выхода из позиции бот продаёт полученную мем-монету обратно в SOL (или другой quote) в том же пуле — результат фиксируется, монета не остаётся в кошельке. Каждый обмен ограничен по price impact и проскальзыванию, проходит те же режимы и учитывается по фактическому чеку. Все транзакции executor идут с priority fee по нагрузке сети с потолком, как советует автор гайда.

## Критерии приёмки

- [ ] executor: операция `SWAP` (exact-in продажа base → quote) в том же пуле через официальный `@meteora-ag/dlmm`; симуляция, лимит impact и минимальный выход на команду; идемпотентность по ключу, как у OPEN/REMOVE; контракт расширен по правилам версионирования, общий JSON-корпус проверяют Python и TypeScript; никакой реальной транзакции в тестах
- [ ] продажа после выхода (`SWAP_AFTER_EXIT`, по умолчанию вкл., настройка в `src/execution/settings.py`): после подтверждённого REMOVE/CLOSE полученный позицией base-токен продаётся отдельной командой; impact выше лимита → частями в пределах лимита, не проходит и часть → токен остаётся + critical alert; сам выход не блокируется; тесты на все три исхода
- [ ] режимы: SHADOW моделирует продажу (котировка + комиссия пула) в учёте; APPROVAL — отдельная карточка подтверждения на каждый обмен (сумма, ожидаемый выход, impact, лимит), без подтверждения ничего не отправляется; LIVE — автоматически; kill switch и дневной стоп продажу после выхода не блокируют; тесты
- [ ] повтор, рестарт и неизвестный исход обмена не дают двойной продажи (UNKNOWN сверяется по command_id, как у прочих команд); тест
- [ ] учёт: P&L позиции включает обмен по суммам receipt; позиция считается закрытой в quote только после продажи (или с явной пометкой «токен не продан»); тест
- [ ] priority fee: executor ставит цену compute unit по свежим prioritization fees сети (перцентиль — настройка) с потолком `PRIORITY_FEE_MAX_LAMPORTS` (по умолчанию 15 000 000 лампортов = 0.015 SOL); фактическая priority fee из receipt входит в издержки учёта; тест executor на потолок и на «нет данных → минимальная настройка»
- [ ] автопокупки для Spot нет (снята пользователем); `src/worker/policy.py` и `src/worker/runtime.py` не трогаются — если подключение без них невозможно, `NEEDS_CONTEXT`
