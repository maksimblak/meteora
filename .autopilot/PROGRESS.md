# Meteora Volume Bot — что осталось

Последняя сборка: `.autopilot/2026-10-18-meteora-volume-bot/` — бот ликвидности для DLMM-пулов Meteora по гайду LexDollar: SHADOW → подтверждение → LIVE, панель FastAPI в Docker, продажа монеты после выхода.

## Договорились — не пересматривать

- Поэтапный запуск «1A»: 7–14 дней SHADOW без денег → сделки с ручным подтверждением → автоматический LIVE.
- «2A»: все DLMM-пулы с жёсткими фильтрами; риск «3B»: до 10% капитала в позиции, риск 1%, максимум 3 позиции, дневной стоп 4%.
- Панель — FastAPI, всё крутится в Docker.
- Метрики GMGN — «Официальное API» по ключу `GMGN_API_KEY`; браузерный сервис только запасной (gmgn.ai отдаёт ему 403).
- Ключа GMGN нет: бесплатный ключ требует $100 на балансе GMGN — «но я не хочу класть деньги»; не предлагать депозит снова.
- GMGN — «сделай реверс», «мы будем работать только по кукам»: браузер-посредник (T21, ADR 0013) — видимое окно на хосте, куки остаются в окне; вход в аккаунт по желанию. Вынос cookie в бот отклонён (обход Cloudflare) — не предлагать.
- Отбор «Как у автора»: устойчивый объём обязателен, всплеск — плюс к баллу; одна позиция на токен (G24).
- Сверка с гайдом — «Всё сейчас»; пакет 2 (перекалибровка стартовых чисел) — после SHADOW.
- Обмен — «В этой сборке»: монета продаётся в SOL после выхода; автопокупку для Spot — «Убрать» (G22).
- Позиция не шире 70 бинов (ADR 0010); поднимать предел нельзя без доработки executor.
- GitHub — «Новый приватный» репозиторий `meteora-volume-bot`, ветка `meteora-volume-bot`.
- Jupiter Tokens API v2 и RugCheck — «Jupiter Tokens API v2 RugCheck API предлагаю ещё добавить, надеюсь апи бесплатный» (2026-10-25): подключены оба, бесплатно и без ключа, включены по умолчанию (ADR 0014); GMGN остаётся первым источником, если настроен.
- Вид панели (2026-10-25): тёмная крипто-тема, «Акцент Meteora», «Тёмная + светлая»; сводка «что происходит сейчас» — во вкладке «Обзор», не отдельной вкладкой («но у нас же есть вкладка обзор»).

## Не доделано

- Слежение за девелопером открытой позиции (`DEV_SOLD`) — только по GMGN; `devBalancePercentage` Jupiter мог бы заменить его без GMGN.
- Полный отчёт RugCheck `/report` (сеть инсайдеров `insiderNetworks`, держатели с пометкой insider) не подключён — 2,5 МБ на BONK; частично закрыл бы долю инсайдеров без GMGN.
- ИИ-мониторинг соцсетей (Kimi/Qwen) — вторая сборка (G19); решить: какие соцсети, модель в облаке или локально; ИИ может только запретить вход или вызвать выход.
- Широкие позиции (>70 бинов) с восстановлением после частичного OPEN — доработка executor (D10).
- Ручной путь оператора: неизвестный исход, частичный выход, 5 неудачных попыток выхода, зависшая продажа — сейчас держат слот до правки базы.
- Пакет 2 сверки: стартовые числа без опоры в источнике (10% от хая, оборот ×10, Spot −60%, `shadow_priority_fee_lamports` 0,001 SOL) — перекалибровать по итогам SHADOW.
- Путь «кандидат → позиция» на живых данных не наблюдался: живой прогон 75 мин (суббота вечер, без RPC и котировщика глубины) — 0 кандидатов из 2216 пулов после прогрева; 2170 ниже порогов объёма автора, почти все остальные — ниже fee/TVL. Подтверждён только на записанных данных. Если в SHADOW кандидатов так и не будет — перекалибровка порогов (пакет 2).
- 1822 из 2216 пулов в живом прогоне — «данные рынка неполные» (INCOMPLETE_MARKET_DATA), API поля отдаёт полностью; вероятно, нет котировщика глубины — проверить в SHADOW с `SOLANA_RPC_URL` и `EXECUTOR_INTERNAL_TOKEN`.
- Лицензия не выбрана.

## Известные баги

- Повторный вход без паузы: на acceptance-стеке после рестарта DOGE-SOL 5 раз подряд открылась и закрылась по `VOLUME_DECAY` за 5–35 с (объём при входе и у монитора расходится) — проверить в SHADOW.
- Отсеянные дешёвыми фильтрами пулы показывают `TOKEN_RISK_UNKNOWN` — шум в журнале.
- Капитал и P&L складываются в единицах quote-токена разных пулов; база лимитов LIVE — бумажная `SHADOW_EQUITY_BASE_UNITS`, а не кошелёк.
- Живые сделки пишутся по цене снимка и модельным издержкам, а не по чеку транзакции.
- Переход в LIVE доверяет файлу `LIVE_PROMOTION_FILE` оператора; покрытие данных для допуска завышено.
- APPROVAL: одобрение позже ~60 с после симуляции тихо отменяет вход.
- Дневной стоп оценивает позицию по снимку любой давности и может сработать поздно.
- Неизвестный объём 5m у открытой позиции не даёт выхода по падению объёма и не предупреждает.
- Кратковременный сбой RPC окончательно отклоняет кандидата; пустой ответ Meteora API считается пустым рынком.
- ATH пула строится по 5-минутным снимкам — пик запуска может быть пропущен; дата создания пула не проверяется на правдоподобие.
- Хранилища DAMM v2 / Raydium CPMM не исключаются из top-10 держателей — концентрация завышается.
- Доход от комиссий в SHADOW может быть завышен до ~1,5 раза при падении объёма после входа.
- Безопасность: PostgreSQL без пароля в одной сети с браузером GMGN; панель не проверяет Host (DNS rebinding); 13 транзитивных advisory в npm-графе Meteora/Solana без совместимого исправления.
- Панель: ложные «расходится» на карточке выхода; readiness api всегда `mode=SHADOW`; не видно, задан ли `GMGN_API_KEY`; нет кнопки «повторить синхронизацию».
- Журнал решений: при сбое записи аудита смена исхода теряется из аудита.
- Мёртвый код: вторые реализации признаков и фильтров в `src/market/features.py`, `quality.py`; `src/core/worker.py`.
- Посредник GMGN: принимает адрес из локальной сети (192.168/10.x) для прослушивания — шире «loopback и Docker»; опрос девелопера (DEV_SOLD) включён и для headless-сервиса; две копии кэша и чтения секрета в `src/gmgn/`; поле лога `token=` маскируется целиком; пропущенные из-за паузы токены остаются в очереди пачки.
- Полный список с подробностями — отчёт сборки (строки `report` в `.autopilot/state.js`).
