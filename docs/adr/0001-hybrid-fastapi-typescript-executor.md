# 0001. Гибридная граница: Python/FastAPI и TypeScript executor

## Контекст

Пользователь выбрал FastAPI для приложения, а сборка, симуляция и подпись транзакций Meteora DLMM надёжно есть только в официальном TypeScript SDK `@meteora-ag/dlmm`.

## Решение

Домен, конвейер, учёт, API и веб-панель живут в Python (FastAPI, worker). Всё, что касается цепи с деньгами — построение, симуляция, подпись, отправка транзакций и котировки, — живёт в отдельном TypeScript-сервисе `executor` на официальном SDK. Python говорит с ним только по внутренней сети Docker версионированными контрактами (`DlmmCommandV2`, `SimulationResultV2`, `GatewayReceiptV2`, `QuoteRequestV1`/`QuoteResultV1`; общий корпус в `contracts/execution/`), с заголовком `x-internal-token`, ключом идемпотентности и, для отправки, mode token и подписанным approval. Кошелёк загружает только executor. Для котировок в SHADOW поднимается отдельный экземпляр `executor-quotes`, у которого кошелька нет по построению (`TRADING_MODE=SHADOW`).

## Почему

- **Всё на Python** (переписать протокол DLMM: раскладку бинов, инструкции, расчёт позиций) отвергнуто: ручная реализация чужого протокола — главный источник денежных ошибок, а каждое обновление программы Meteora пришлось бы догонять самостоятельно.
- **Всё на TypeScript** отвергнуто: пользователь прямо попросил FastAPI, а доменная логика, учёт и тесты на Python уже были основной частью работы; второй язык для них ничего не даёт.
- **SDK внутри Python-процесса через мост** (Node как подпроцесс без сетевой границы) отвергнут: ключ кошелька оказался бы в одном процессе с веб-панелью и аналитикой, а изоляция секрета — требование R28i и §8.5.

## Последствия

- Ключ никогда не попадает в API, worker, логи и ответы; веб-панель взломать недостаточно, чтобы подписать транзакцию.
- Два языка, две сборки и два набора тестов; контракт приходится держать синхронным с обеих сторон (общий JSON-корпус проверяют и Python, и TypeScript; неизвестная версия отклоняется).
- Неприятное: executor не делает обмен токенов (D08). Вход Bid-Ask ниже цены идёт только в quote-токене, Spot-вход возможен лишь при наличии обоих токенов в кошельке, а автоматического swap перед входом нет.
- Неприятное: compose-сервис `executor` (профиль `live`) не получает ни одной переменной из `docker-compose.yml` — для APPROVAL/LIVE оператор сам пишет `docker-compose.override.yml` с секретными файлами (см. `docs/runbook.md`).
- Сетевой вызов добавляет точку отказа: неизвестный результат отправки сверяется по `GET /v1/commands/{id}`, а не отправляется повторно.
