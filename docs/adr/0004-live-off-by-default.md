# 0004. LIVE выключен по умолчанию

## Контекст

Пользователь выбрал поэтапный запуск (1A): сначала 7–14 дней SHADOW без денег, затем сделки с ручным подтверждением, и только потом автоматический LIVE; доходность при этом не гарантирована.

## Решение

Свежая база стартует в `SHADOW`; после рестарта действует сохранённый в базе режим — рестарт его не повышает и не понижает. Режим хранится в PostgreSQL и меняется только через `POST /api/v1/mode/transitions` (или форму `/mode`): повышение `SHADOW → APPROVAL → LIVE` требует promotion evidence, повторного ввода токена оператора и явного подтверждения, прямой `SHADOW → LIVE` запрещён. Переменная `TRADING_MODE` режим не включает: она лишь выбирает, для какого режима подключить шлюз исполнения. В APPROVAL каждая сделка отправляется только после одноразового подписанного approval с TTL, отметок ручного чеклиста и свежей симуляции. В LIVE executor дополнительно требует файл LIVE promotion evidence (`LIVE_PROMOTION_FILE`: не меньше 10 циклов APPROVAL, сверенные receipts, готовые RPC и кошелёк, пройденный чеклист). Понижение режима и kill switch доступны всегда и применяются сразу.

## Почему

- **Включение LIVE одним флагом в `.env`** отвергнуто: это прямо противоречит выбранному поэтапному запуску (§3, §10) и делает одну опечатку в конфиге денежным событием.
- **Сразу APPROVAL без SHADOW-окна** отвергнуто: пороги `guide-v1` — гипотеза из гайда, без недели наблюдений нет ни статистики, ни проверки, что данные вообще приходят.
- **Автоматическое повышение по метрикам без человека** отвергнуто: ни один числовой результат не доказывает будущую прибыль (§7.1); gate подтверждает только техническую и статистическую готовность, решение остаётся за оператором.

## Последствия

- Свежая установка не может потратить деньги: без кошелька, executor-секретов и evidence шлюз просто не собирается, а входы APPROVAL/LIVE отменяются (`EXECUTION_GATEWAY_NOT_CONFIGURED`).
- Путь до LIVE долгий: минимум 7 полных UTC-суток SHADOW (рекомендовано 14), не меньше 20 завершённых paper-позиций или явная отметка о недостатке статистики, положительный net expectancy, просадка не выше 4%, покрытие данных от 99%, затем 10 подтверждённых циклов APPROVAL.
- Неприятное: открытый critical alert блокирует допуск в APPROVAL, а закрыть его из панели можно только для kill switch (снятием kill switch) — `DAILY_STOP_TRIGGERED` и другие alerts оператор закрывает вручную (см. `docs/runbook.md`).
- Неприятное: при настройках по умолчанию LIVE закрыт ещё и требованием свежих данных GMGN, а их даёт только ключ GMGN OpenAPI, который оператор заводит сам (G18, G20, ADR 0002).
- Неприятное: если оператор вручную понизил режим до SHADOW, выход позиции, открытой в APPROVAL, панель не одобряет (только аварийные выходы под дневным стопом или kill switch с политикой `ORDERLY_EXIT`); спецификация этот случай не регулирует.
