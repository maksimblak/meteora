# 0007. Якорь входа в снимке, ключ позиции и price impact — у executor

## Контекст

План: Python строит команду входа по своему плану, executor получает готовый файл ключа позиции и сам проверяет price impact. T09 показал, что любой вход в APPROVAL/LIVE отменяется: в снимке нет active bin и decimals (`ENTRY_ANCHOR_UNAVAILABLE`), файла ключа позиции никто не создаёт, readiness отвечает 503 без измерения impact.

## Решение

- Active bin и decimals токенов — часть снимка пула. Они читаются через RPC из аккаунта пула и mint'ов, а перед входом active bin перечитывается свежим; без них не-SHADOW команда не строится.
- Ключ новой позиции создаёт executor в момент команды открытия, подписывает им инициализацию и возвращает адрес позиции в receipt. Python берёт адрес позиции только из receipt.
- Price impact executor берёт из котировки официального SDK; превышение лимита отклоняет вход, а готовность к LIVE зависит от этой возможности.

## Почему

- **Python заранее выводит адрес и готовит файл ключа позиции** отвергнуто: ключ позиции подписывает транзакцию, а подписывающий материал живёт только в executor (ADR 0001). Адрес, вычисленный заранее, вдобавок расходится с сетью, если открытие не состоялось; источник истины — receipt.
- **Active bin из последнего sweep** отвергнут: бин из sweep устаревает за минуты, а executor всё равно сверяет бин в симуляции (`ACTIVE_BIN_DRIFT`) — старый бин давал бы только отказы или ликвидность не там.
- **Python считает impact сам по бинам** отвергнуто: Data API глубины по бинам не даёт, а расчёт по устройству пула — ровно то, что ADR 0001 оставил официальному SDK.

## Последствия

- Неприятное: Python читает аккаунт пула по известной раскладке программы DLMM — единственное место, где он знает внутренности протокола. Обновление программы Meteora со сменой раскладки сломает якорь; входы тогда закроются, а не уйдут по неверному бину.
- Адрес позиции известен только после подтверждённого открытия; пока исход отправки неизвестен, план остаётся в исполнении до сверки по команде.
- Без котировки SDK LIVE не готов, а входы APPROVAL/LIVE закрыты; в SHADOW её отсутствие заменяет консервативная модель (ADR 0008).
