# 0008. Конвейер на живых данных: короткие окна из счётчиков, глубина из котировки

## Контекст

План читал окно 5m, глубину и полноту снимка из Data API и сканировал весь universe. T11 показал: на живом API каждый пул отклоняется (`INCOMPLETE_MARKET_DATA`, `LOW_DEPTH`, `PRICE_IMPACT_HIGH`), всплеск и `VOLUME_DECAY` не срабатывают, а universe — 139 тыс. пулов.

## Решение

- Короткие окна считаются разницей кумулятивных счётчиков объёма и комиссий соседних снимков. Малая отрицательная разница — шум и обнуляется; крупная отрицательная, слишком короткий или слишком длинный интервал дают `UNKNOWN` для окна. Источник окна пишется в решение.
- Кандидатов прогревает история объёма API с шагом 5m, а не накопление своих снимков.
- Universe сужается фильтром на стороне API: по умолчанию объём за 24 ч > 0 (около 2 тыс. пулов); полный обход — настройкой.
- Полнота снимка определяется по полям, которые API реально даёт.
- Глубина и price impact измеряются только для кандидатов после дешёвых фильтров — read-only котировкой executor на эталонный размер, отдельным экземпляром без кошелька. Нет котировки — флаг `DEPTH_UNAVAILABLE`: в SHADOW кандидат идёт дальше с консервативной моделью проскальзывания, в APPROVAL/LIVE вход закрыт.
- Сигналы API — чёрный список пула, верификация токенов, отключённая freeze authority — входят в hard filters.

## Почему

- **Наименьшее окно API (30m) вместо 5m** (ADR 0005) отвергнуто: на получасовом окне всплеск и падение объёма видны слишком поздно, а гайд работает объёмом в минуту.
- **История 5m из API для каждого пула на каждом цикле** отвергнута: при общем лимите около 2 запросов в секунду обход 2 тыс. пулов длится дольше самого окна. История берётся только для прогрева кандидатов.
- **Полный обход 139 тыс. пулов** отвергнут: подавляющее большинство без объёма за сутки и кандидатом стать не может, а обход съедает лимит запросов, нужный кандидатам и открытым позициям.
- **Глубина в Python по бинам** отвергнута: Data API глубины по бинам не даёт, а расчёт по устройству пула ADR 0001 оставил SDK.
- **Без глубины — отказ и в SHADOW** отвергнут: без поднятого executor SHADOW не накопил бы ни одного наблюдения (та же логика, что D09 в ADR 0002).

## Последствия

- Короткое окно существует, только пока бот снимает пулы достаточно часто: окно 5m берётся из интервала не короче 4,5 минуты, частые снимки суммируются; пропуск цикла или рестарт дают `UNKNOWN` окна, а не догадку.
- Неприятное: счётчики API не монотонны, и граница «шум или сброс счётчика» — эвристика с порогами; ошибка в ней даёт ложный ноль или ложный `UNKNOWN`.
- Неприятное: в SHADOW без котировок paper-результат считается на консервативной модели проскальзывания и не равен тому, что дал бы реальный вход.
- Ради измерения глубины даже в SHADOW нужен ещё один сервис — экземпляр executor для котировок, без кошелька.
