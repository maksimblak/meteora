# 0014. Бесплатные источники токена — Jupiter Tokens API v2 и RugCheck

## Контекст

Без ключа GMGN объём токена был суммой его DLMM-пулов Meteora (`TOKEN_VOLUME_POOL_ONLY`), числа сделок и участников не было вовсе (`VOLUME_PARTICIPANTS_UNAVAILABLE` закрывал LIVE), а mint/freeze authority без RPC оставались неизвестны. Живой прогон 2026-10-24 дал 0 кандидатов из 2216 пулов: 2170 отсеялись по объёму автора, посчитанному только по DLMM. ADR 0013 оставил Jupiter + RugCheck запасным путём; 2026-10-25 пользователь попросил подключить оба («Jupiter Tokens API v2, RugCheck API — предлагаю ещё добавить, надеюсь, API бесплатный»).

Живая проверка 2026-10-25, без ключа:

- Jupiter `GET https://api.jup.ag/tokens/v2/search?query=<до 100 mint>` — 62 токена топ-100 пулов Meteora одним запросом: `stats5m`/`stats1h` (объём покупок и продаж, число сделок и трейдеров, органический объём), `mcap`, `organicScore` и `organicScoreLabel`, `audit` (mint/freeze, доля топ-держателей, доля девелопера), `firstPool.createdAt`. Нули и `false` Jupiter в ответ не пишет: пустое окно — `{"volumeChange": -100}`, живая mint authority — без `mintAuthorityDisabled`, зато с адресом в `mintAuthority`.
- RugCheck `GET https://api.rugcheck.xyz/v1/tokens/{mint}/report/summary` — 30 мемкоинов: у чистых `score_normalised` 1 и пустой `risks`; `danger` — «Top 10 holders high ownership», «Single holder ownership», «High ownership», «Mint Authority still enabled», «Large Amount of LP Unlocked». Все три токена с органичностью Jupiter 0 тоже были с `danger`.
- DexScreener отдаёт то же окно 5m и сделки по пулам, но без числа трейдеров; Jupiter закрывает это сам — DexScreener не подключён.

## Решение

- **Jupiter читается на весь цикл, до решений.** Перед отбором worker спрашивает Jupiter о верхних `JUPITER_MAX_TOKENS` (500) токенах цикла пачками по 100, не чаще 0,4 запроса в секунду (0,8 с бесплатным ключом), кэш 2 минуты. Показание прикрепляется к токену с дешёвых фильтров, поэтому решает без единого запроса к RPC.
- **Что решает свежее показание Jupiter (guide-v1):** объём токена, если нет свежего GMGN (`token_volume_source=JUPITER`), — так, как автор смотрит объём токена в GMGN; капитализация (GMGN → Jupiter → Data API); нижняя граница возраста по первому пулу; сделки и трейдеры за 5 минут — вместо отсутствующих у пула (горстка кошельков, делающих весь объём, — `ARTIFICIAL_VOLUME_CONFIRMED`); оценка органичности `low` — `ARTIFICIAL_VOLUME_SUSPECTED` во всех режимах, как wash trading у GMGN; mint/freeze, которые не знают другие источники (опаснее — побеждает); доля девелопера больше нуля без цифры GMGN — флаг `DEVELOPER_HOLDS_TOKENS`, в LIVE отказ.
- **RugCheck — только для глубокой проверки**, не чаще запроса в секунду, кэш 30 минут. Любой риск `danger` — `RUGCHECK_DANGER` во всех режимах; `warn` — только в доказательствах.
- **Оба источника необязательны.** Выключен, сбой или токен неизвестен — показание с причиной (`jupiter_status`, `rugcheck_status`); ничего не закрывается. Сбой Jupiter возвращает прежнее поведение (суммы DLMM, флаги), сбой RugCheck даёт флаг `RUGCHECK_UNAVAILABLE`. GMGN, если настроен, по-прежнему первый.
- По умолчанию включены в compose (`JUPITER_API_URL`, `RUGCHECK_API_URL`); пустое значение в `.env` выключает. В приёмке выключены — она без внешней сети.

## Почему

- **Jupiter в дешёвых фильтрах, а не после них, как GMGN:** пачка в 100 токенов стоит один запрос, а объём токена — первый фильтр автора. Иначе токен с малым объёмом на Meteora, но большим на других площадках отсеивался бы суммой пулов, а токен, проходящий по сумме пулов, тратил бы глубокую проверку.
- **`low` и `danger` — отказ, а не флаг:** это прямые признаки накрутки и рага; в SHADOW они дали бы сделки, которых LIVE не сделает, и исказили бы статистику допуска.
- **Доля топ-держателей Jupiter — только доказательство:** неизвестно, исключает ли Jupiter хранилища пулов, а порог top-10 у бота уже есть (RPC, GMGN).
- **Отсутствующий процент — неизвестность, не ноль:** у 42 из 62 токенов нет `devBalancePercentage`; считать это нулём значило бы разрешать LIVE на догадке.

## Последствия

- Без GMGN бот теперь видит объём токена по всем площадкам, сделки и трейдеров, органичность и раг-риски. GMGN по-прежнему единственный источник долей insiders, bundling, phishing, снайперов, total fees и ATH токена; LIVE без него закрыт, пока `GMGN_REQUIRED_FOR_LIVE` не `false`.
- Каждые ~2 минуты до 5 запросов к Jupiter; при 429 — пауза до `x-ratelimit-reset`, не дольше 5 минут.
- Решения стали подробнее (строки `jupiter_*`, `rugcheck_*`); `outcome_key` их не учитывает, база не растёт от них.
- Слежение за девелопером открытой позиции (`DEV_SOLD`) по-прежнему только по GMGN.
