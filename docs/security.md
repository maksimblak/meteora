# Безопасность и модель угроз

Документ для одного оператора, который запускает бота у себя на Windows-компьютере через Docker Desktop. Здесь — что защищаем, от чего, чем именно и что остаётся на совести оператора. Значения секретов не приводятся нигде: только имена переменных.

## Что защищаем

| Актив | Где живёт | Чем грозит утечка или подмена |
|---|---|---|
| Ключ кошелька Solana | файл `WALLET_KEYPAIR_FILE`, только в контейнере `executor` (профиль `live`) | полная потеря средств кошелька |
| Токен оператора `APP_OPERATOR_TOKEN` | `.env` или файл `APP_OPERATOR_TOKEN_FILE`, контейнер `api` | любые изменения: смена режима, approval сделок, снятие kill switch |
| Секрет сессии `APP_SESSION_SECRET` | `.env`/файл, контейнер `api` | подделка cookie веб-сессии |
| Внутренний токен executor `EXECUTOR_INTERNAL_TOKEN` | `.env`/файл; worker, `executor`, `executor-quotes`; в `api` — только через `*_FILE` | доступ к симуляции, котировкам и командам executor из внутренней сети |
| Mode token `EXECUTOR_MODE_TOKEN` и секрет approval `EXECUTOR_APPROVAL_SECRET` | файлы для executor и worker/api в APPROVAL/LIVE | возможность отправить команду или подписать approval в обход панели |
| URL RPC с ключом провайдера `SOLANA_RPC_URL`, `HELIUS_API_KEY` | `.env` | расход чужой квоты, раскрытие ключа провайдера |
| Ключ GMGN OpenAPI `GMGN_API_KEY` / `_FILE` | `.env`/файл, только контейнер `worker` | расход вашего тарифа GMGN, бан ключа за превышение лимита |
| База PostgreSQL | volume `postgres-data` | подмена режима, позиций, журнала решений |

## Кошелёк и ключи

- Ключ кошелька загружает только TypeScript `executor` (ADR 0001); API, worker и веб-панель его не видят. В ответах, логах и файле состояния executor ключей нет: ключ новой позиции создаётся в памяти при симуляции и не пишется на диск.
- Shadow-стек (`docker compose up --build` без профиля `live`) кошелька не требует и не содержит. Сервис `executor-quotes` закреплён в `TRADING_MODE=SHADOW` и кошелёк не загружает по построению.
- Отправка денег требует сразу: `TRADING_MODE=APPROVAL|LIVE` у executor, файл кошелька, `EXECUTOR_STATE_FILE`, внутренний токен, mode token, для APPROVAL — секрет approval, для LIVE — валидный `LIVE_PROMOTION_FILE`. Без любого из них executor отвечает `not_ready` и ничего не подписывает.
- **Обмен токенов ограничен продажей монеты после выхода** (операция `SWAP`, G22): только в том же DLMM-пуле через официальный SDK, без агрегаторов. Executor складывает все части продажи по позиции и отказывает (`409 SWAP_EXCEEDS_EXIT_RETURNS` при отправке, ничего не отправлено), если они больше монеты, которую вернули подтверждённые выходы этой позиции (`delta_x` из квитанций); остальные монеты кошелька бот не продаёт. У каждой команды — лимит price impact (`SWAP_MAX_PRICE_IMPACT_BPS`), минимальный выход в сети (`SWAP_SLIPPAGE_BPS`), симуляция и срок действия; часть с неизвестным исходом только сверяется и никогда не отправляется повторно. В APPROVAL каждая часть подтверждается отдельно, как вход и выход.
- **Priority fee ограничен потолком на транзакцию** (`PRIORITY_FEE_MAX_LAMPORTS`, по умолчанию 0,015 SOL): цена compute unit режется так, чтобы ни одна транзакция не заплатила больше, при любом всплеске сетевых комиссий. Нечитаемое значение `PRIORITY_FEE_*` не даёт executor стартовать — executor с неверным потолком торговать не начнёт.
- Используйте **отдельный горячий кошелёк** с небольшой суммой, никогда не основной. Ручная проверка executor — только на devnet и только с одноразовым кошельком (`executor/README.md`).
- Файлы ключей и секретов держите вне папки проекта или хотя бы вне Git; `.gitignore` исключает `.env` и `.env.*` (кроме `.env.example`), а `.dockerignore` не пускает `.env`, `docker-compose.override.yml`, `.git` и локальные кэши даже в контекст сборки образов — Dockerfile копируют только явно перечисленные папки кода. Скрипт `scripts/verify-delivery.ps1` проверяет, что в поставке нет `.env`, ключей и secret-файлов.

## Токен оператора, сессии и CSRF

- Чтение (страницы панели, `GET /api/v1/*`) открыто локальному оператору без входа — панель опубликована только на `127.0.0.1:8000`.
- Любое изменение требует аутентификации: API-клиенты шлют `Authorization: Bearer <токен>`, веб-панель один раз меняет токен на cookie `mvb_session` (HMAC-подпись, `HttpOnly`, `SameSite=Strict`, `Secure` при HTTPS). Каждая изменяющая форма несёт CSRF-токен сессии (поле `csrf_token` или заголовок `X-CSRF-Token`); без него — `403 CSRF_FAILED`.
- Действия, которые повышают риск, необратимы или открывают допуск (approval сделки, повышение режима, снятие kill switch, закрытие critical alert), дополнительно требуют повторного ввода токена и явной галочки подтверждения (`confirm` / `confirm_irreversible`).
- Токены, CSRF и подпись cookie сравниваются по байтам UTF-8 за постоянное время: любой присланный текст (в том числе не-ASCII) даёт отказ `401`/`403`, а не ошибку сервера. Ссылки «вернуться» и `next` после входа ведут только на пути этой панели (`//host` и `\` отбрасываются).
- Если `APP_OPERATOR_TOKEN` не задан, все изменяющие действия закрыты (`503 OPERATOR_AUTH_NOT_CONFIGURED`), а панель так и пишет — стек при этом запускается.
- Токены сравниваются за постоянное время и не логируются. В аудит попадает метка вида `operator:session:<8 символов id сессии>`, не токен.
- Без `APP_SESSION_SECRET` ключ сессий случайный на каждый запуск `api`: после рестарта нужно войти заново.
- Ограничения: один токен на одного оператора, ролей нет; защиты от перебора токена нет — защищает только то, что порт слушает `127.0.0.1`. Используйте длинный случайный токен (32+ символа).

## Редактирование логов

- Секреты перечислены в одном месте — реестре `src/core/secrets.py`: `DATABASE_URL`, `APP_OPERATOR_TOKEN`, `APP_SESSION_SECRET`, `HELIUS_API_KEY`, `EXECUTOR_INTERNAL_TOKEN`, `EXECUTOR_MODE_TOKEN`, `EXECUTOR_APPROVAL_SECRET`, `GMGN_API_KEY`, `GMGN_BRIDGE_TOKEN`, `TELEGRAM_BOT_TOKEN`, путь `WALLET_KEYPAIR_FILE`. По нему же работают маскирование `AppConfig.redacted()`, редактор логов и список секретов в `/settings` — списки не расходятся. Новый секрет добавляется только в реестр.
- Логи Python — JSON (structlog). Значения полей с `token`, `secret`, `password`, `api_key`, `private_key`, `keypair`, `dsn`, `database_url` в имени заменяются на `[REDACTED]`; кроме того, точные значения всех секретов реестра, пароль из `DATABASE_URL` и ключевые части адресов провайдеров (значения query-параметров вроде `api-key` в `SOLANA_RPC_URL`, пароль в `user:password@`, длинные сегменты пути) вырезаются из любых строк записи.
- Трасса исключения (`exc_info` — в том числе запись uvicorn «Exception in ASGI application» после ответа 500) сначала форматируется в текстовое поле `exception` и только потом проходит тот же редактор; объект исключения в лог не попадает. Это проверяет тест `tests/foundation/test_f3_secrets.py` для каждого секрета реестра.
- Ограничение: вырезаются точные значения. Секрет, вставленный оператором в свободный текст в изменённом виде (часть строки, другой регистр), редактор не узнает — не вставляйте секреты в причины переходов, закрытия alerts и комментарии к approval.
- Ответ GMGN, в котором поле `error` совпадает с ключом или содержит его кусок (в любом регистре), не становится причиной отказа: вместо него — `HTTP_401`/`HTTP_403`/`RATE_LIMITED`/`API_ERROR`; ключ не попадает ни в решение, ни в health, ни в лог.
- `GET /api/v1/config/effective` и страница `/settings` показывают конфигурацию с замаскированными секретами и только факт «задано/не задано» для секретных переменных.
- Адрес кошелька в логах допустим (§8.5), секретный материал — нет.

## Сеть Docker

| Сервис | Порт | Доступ |
|---|---|---|
| `api` | `127.0.0.1:8000` | единственный опубликованный порт, только с этого компьютера |
| `worker` | 9100 (`expose`) | health и метрики, только внутренняя сеть compose |
| `executor`, `executor-quotes` | 3000 (`expose`) | только внутренняя сеть; все `/v1/*` требуют `x-internal-token` |
| `gmgn` (профиль `gmgn`) | 8080 (`expose`) | только внутренняя сеть |
| `postgres` | не опубликован | только внутренняя сеть; `POSTGRES_HOST_AUTH_METHOD: trust` |

- Не публикуйте порты `postgres`, `executor`, `worker` наружу и не меняйте `127.0.0.1:8000` на `0.0.0.0:8000`: БД в compose без пароля, а executor с кошельком полагается на изоляцию сети.
- Для удалённого доступа к панели используйте SSH-туннель или VPN, а не проброс порта в интернет; панель не рассчитана на публичный интернет (нет HTTPS из коробки, нет rate limit).
- Контейнеры работают от непривилегированных пользователей (`app` uid 10001, `node`, `pwuser` у `gmgn`).

## GMGN и внешние сайты

- Основной путь — официальный GMGN OpenAPI (G20): ключ идёт только в заголовке `X-APIKEY` исходящего запроса worker, никогда в URL, лог, ответ или причину отказа; в api ключ не передаётся. Клиент держит 80% лимита тарифа и сам замолкает после отказа ключа или лимита — чтобы не продлевать бан.
- Запасной путь — сервис `gmgn`: открывает публичную страницу токена как обычный посетитель в официальном Playwright Chromium. Никаких капч, сервисов-решателей, stealth-плагинов, подмены user agent и отпечатков, аккаунтов и cookie пользователя (§6.7, проверяется тестом `tests/gmgn/test_gmgn_deployment.py`). Сейчас gmgn.ai через Cloudflare отдаёт headless-браузеру 403, и сервис честно отвечает `UNAVAILABLE` — обходить это проект не будет.

## Зависимости и цепочка поставки

- Версии заморожены: `uv.lock` (Python), `executor/package-lock.json` (Node), `services/gmgn/uv.lock` (браузерный сервис, отдельно от основного образа). Установка — `uv sync --frozen`, `npm ci --ignore-scripts` (скрипты пакетов при установке не выполняются).
- Базовые образы закреплены по тегу, не по digest: `python:3.12-slim-bookworm`, `node:22-bookworm-slim`, `postgres:16-bookworm`, `mcr.microsoft.com/playwright/python:v1.63.0-noble`; `uv==0.12.4`. Тег может быть перезаписан издателем — для максимальной воспроизводимости закрепите digest в своём форке.
- Самая чувствительная зависимость — `@meteora-ag/dlmm` и `@solana/web3.js` в executor: они видят ключ. Обновляйте их только осознанно, с прогоном `npm run check --prefix executor` и ручной проверкой на devnet.
- Автоматического аудита уязвимостей в каноническом check нет; перед переходом в LIVE прогоните `npm audit --prefix executor` и проверку Python-зависимостей своим инструментом.

## Угрозы и ответ на них

| Угроза | Что мешает | Что остаётся |
|---|---|---|
| Утечка ключа через веб-панель или логи | ключ только в executor, редактирование логов | компрометация самого компьютера или Docker Desktop |
| Случайная сделка реальными деньгами | SHADOW по умолчанию, gates, approval с TTL, отсутствие кошелька в shadow-стеке (ADR 0004) | оператор, сознательно включивший LIVE |
| Повторная отправка транзакции после сбоя | идемпотентный ключ, сверка неизвестного результата по цепи, durable-состояние (ADR 0003) | частично прошедший выход — ручной разбор (`docs/runbook.md`) |
| CSRF с другого сайта в браузере оператора | `SameSite=Strict` + CSRF-токен | — |
| Подмена решений через «чистые» недостающие данные | fail-closed, флаги недоступности (ADR 0002); неизвестная доля девелопера или тема без имени и тикера закрывают LIVE | ручной чеклист не проверяется машиной; в LIVE его никто не проходит — Twitter/хайп, PvP-копии и кластеры Bubblemaps там не проверяются вовсе (`docs/runbook.md`, §2.5) |
| Rug pull, манипуляция объёмом | hard filters, накрутка по total fees против капы и обороту пула, wash trading GMGN, отказ при доле девелопера в LIVE, выход `DEV_SOLD`, лимиты 10% / 1% / 3 позиции / 4% в день | ни один фильтр не делает токен безопасным; потеря позиции возможна |
| Продажа лишнего или повторная продажа при обмене | сумма частей ≤ монеты, вернувшейся из позиции (проверка executor), лимит impact и минимальный выход на команду, неизвестный исход только сверяется | непроданная монета остаётся в кошельке под alert до решения оператора; часть с неизвестным исходом держит слот позиции — ручного пути в панели нет |
| Переплата сетевых комиссий | потолок `PRIORITY_FEE_MAX_LAMPORTS` на транзакцию | при нагрузке сети транзакция с потолком может не пройти — потолок поднимает оператор |
| Утечка секретов в Git или поставку | `.gitignore`, только имена в `.env.example`, `scripts/verify-delivery.ps1` | секреты, положенные оператором в другие файлы с нестандартными именами |
